# NUPS Batch 17 Test Identity Matrix

**Date:** 2026-08-22  
**Scope:** Distinct authenticated sessions required for protected-evidence and cross-venue acceptance

## Required matrix

| Test identity | Required NUPS role | Venue | Purpose | Start-state result |
|---|---|---|---|---|
| Global administrator | SOVEREIGN or PLATFORM_ADMIN | global | global-role cross-venue behavior and audit reconciliation | A global/owner administrative path exists, but a disposable dedicated test session was not provisioned |
| Venue A manager | VENUE_MANAGER or VENUE_OWNER | Venue A | same-venue protected-evidence allow | An active owner-class venue identity exists; token/session must be supplied securely for the manual harness |
| Venue A door operator | DOORMAN or DOOR_GIRL | Venue A | identity allow, tax/biometric denial | No dedicated authenticated Batch 17 door test session was available at run start |
| Venue A ordinary operator | BARTENDER or DJ | Venue A | identity/contract denial | No dedicated authenticated Batch 17 ordinary-staff test session was available at run start |
| Venue B manager | VENUE_MANAGER | isolated Venue B / DEMO venue | wrong-venue denial | No dedicated second-venue manager session was available at run start |

## Safety decision

No existing employee or customer account was repurposed. No real operator’s role or venue was changed. No fake PASS was generated by service-role simulation.

A Base44 `NUPSUser` record without a real authenticated Base44 session is not sufficient for Batch 17 E2E evidence. Static policy calls and service-role requests remain useful controls, but they are not equivalent to the caller identity, authentication and authorization path used in production.

## Execution boundary

The secure manual command is:

```text
npm run test:nups-batch17-authenticated
```

It requires short-lived runtime tokens and synthetic evidence IDs listed in `docs/runbooks/NUPS-BATCH17-AUTHENTICATED-ACCEPTANCE.md`. Missing variables produce a `BLOCKED` result and exit code 2 without printing any token.

## Cleanup requirement

Any dedicated test users created later must be DEMO/SANDBOX scoped, must not receive REAL payment or production evidence access, and must be suspended or removed from operational access after acceptance while preserving security-audit records.
